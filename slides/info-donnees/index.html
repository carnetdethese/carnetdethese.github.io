1.1 Moteurs de recherche

Définition :
Un moteur de recherche indexe les pages web, y cherche les résultats et les trie pour vous.

  1. Crawl (par des robots)
  2. Indexation (base de données géante)
  3. Requête utilisateur & classement par pertinence

Types de moteurs et portails

  • Moteur : automatique (Google, Bing, DuckDuckGo, Qwant, Ecosia)
  • Portail web : gestion humaine (annuaires spécialisés)

Exemple : Google a inventé le PageRank : plus une page est liée par d’autres, plus elle “monte”.

1.3 Veille informationnelle

Pourquoi faire une veille ?

Veille : suivre de façon organisée et continue un domaine pour en repérer les évolutions.

  • Juridique et réglementaire : JO, Légifrance, CNIL
  • Technologique, sectorielle : outils, pratiques, innovations
  • D’image : ce qui se dit de son administration en ligne
  • Ne pas tout laisser aux algorithmes (bulle de filtres !)

Problèmes à l’ère des algorithmes

  1. Bulle de filtres : les algorithmes construisent « notre » réalité
  2. Viralité : prime à l’émotion, parfois à la désinformation
  3. Uniformisation et biais : moins de diversité, débat fragmenté
  4. Passivité : on consomme au lieu de chercher

Outils de veille

  • Flux RSS : s’abonner aux nouveautés d’un site
  • Agrégateurs (Feedly, Inoreader, NewsBlur, Thunderbird)
  • Alertes personnalisées (Google Alerts)
  • Outils de social media marketing (Hootsuite, Meltwater)
  • Alertes institutionnelles & newsletter spécialisées (CNIL, Cour des comptes, JO, INSEE, Service-public.fr, etc.)
  • Curation & bookmarking collaboratif (Pearltrees, Scoop.it, Wakelet, Linkwarden)
  • Plateformes spécialisées (ResearchGate, HAL, Gallica, Google Scholar)
  • Réseaux sociaux (X, LinkedIn, Bluesky, Reddit…)

Bonnes pratiques de veille

  • Combiner plusieurs méthodes et outils
  • S’organiser (étiquettes, dossiers, alertes) ;
  • Pensée critique et diversité ;
  • Mises à jour régulières et suppression les flux “morts”.

1.4 Évaluer la fiabilité d’une source

  • Qui publie ? (auteur, institution…)
  • Quand (date, actualisation) ?
  • Vérifier avant de partager
  • Croiser les sources : sortir du site pour voir ce qu’on en dit (lecture latérale)

  • Outils de fact-checking

2. Gérer les données

2.1 Définitions de base

  • Donnée : élément brut, sans interprétation immédiate ;
  • Information : organisation et signification de la donnée ;
  • Métadonnée : donnée qui décrit une donnée (titre, auteur, date, format, licence).

Les données sont des représentations élémentaires d’une information, exploitable par un système informatique.

Les grands enjeux de la donnée

  • Économique : ciblage, optimisation, nouveaux marchés de la donnée
  • Démocratique : open data, transparence, contrôle citoyen
  • Éthique/juridique : respect de la vie privée, consentement, non-discrimination
  • Sécurité : cybermenaces, intégrité de l’information
  • Organisation : modernisation, efficacité, automatismes

2.5 API : définition

Une API (Application Programming Interface) est une interface qui permet à un logiciel d’accéder à des ressources ou fonctions offertes par un système ou un autre logiciel.

2.6 Collecte de la donnée : fiabilité et légalité

Fiabilité : peut-on faire confiance à la donnée collectée ?

  • Une donnée mal collectée fausse tout le reste du cycle
  • Fiabilité ≠ qualité : une source sûre peut fournir une donnée inadaptée à l’usage

Légalité — RGPD

  • Toute collecte de données personnelles repose sur l’une des 6 bases légales (art. 6)
  • Administration : le plus souvent mission d’intérêt public ou obligation légale, rarement le consentement
  • Une finalité déterminée, des données limitées au nécessaire
  • Outils : registre des traitements, AIPD si risque élevé, DPO (obligatoire pour un organisme public)

2.7 Stockage local et cloud

2.8 Organisation des dossiers et nommage

Établir des conventions d’organisation

  • À des fins d’archivage
  • Pour la collaboration
  • Recherche

Pourquoi bien nommer ses fichiers ?

  • Gagner du temps et diminuer le stress
  • Prévenir les accidents (suppression accidentelle, oubli, etc.)
  • Faciliter le partage
  • Travailler sur le bon document

Bonnes pratiques

Beaucoup de propositions différentes par diverses institutions (Conseil de l’Europe, Programme Vitam, Projet Datacc’, MIT, l’INRAE)

En résumé :

  • Date au format AAAA-MM-JJ (norme ISO 8601), en début de nom
  • Pas d’espace ni de caractères spéciaux (& * % $ £ ° { ! @) : - ou _
  • Noms courts, dossiers clairs
  • Ne jamais distinguer deux fichiers par la seule casse (DATA / data)
  • Numéroter sur deux chiffres : 01, 02… 10
  • Pas de v2_def_final : utiliser l’historique des versions (OneDrive, Nextcloud…) ou git

3.1 Tableur ou base de données ?

AspectTableurBase de données
Structure et relationsDocument bidimensionnel, peu ou pas de relations entre fichiersOrganisation en tables avec relations explicites (clés étrangères)
Capacité et gestionLimitée, devient difficile à gérer avec de gros volumesTrès grande capacité, conçu pour gérer de vastes ensembles de données
Flexibilité et utilisationApproprié pour petites listes, budgets, analyses simplesIdéal pour gérer des données complexes, relations et applications professionnelles

3.2 Traiter et visualiser sur tableur

Les bases du traitement

  • Une cellule = une valeur ; une colonne = un type de donnée
  • Format des cellules (erreurs fréquentes : texte ≠ nombre ≠ date)
  • Formules de base :
    SOMME(), MOYENNE(), NB() / NBVAL(), SI(), NB.SI(), RECHERCHEV() / RECHERCHEX()
  • Trier, filtrer, rechercher
  • Mise en forme conditionnelle : colorer les cellules selon un critère
  • Équivalents : LibreOffice Calc (libre, .ods), Google Sheets

Visualisation

  • Graphiques : histogrammes, camemberts, courbes
  • Toujours choisir le graphique qui traduit le mieux son message !
  • Tableaux croisés dynamiques pour résumer et croiser des variables

3.3 Les bases de données

Une base de données est un ensemble d’informations organisées de manière logique de sorte qu’elles puissent être accessibles et utilisées ultérieurement par un programme informatique.

Source : Airmakers

  • Des tables reliées entre elles, gérées par un SGBD (système de gestion de base de données)
Vocabulaire fondamental des bases
ConceptDéfinition
TableEnsemble de données du même type (ex : élèves)
ChampColonne, attribut (nom, date…)
EnregistrementLigne (un individu, une opération)
Clé primaireIdentifiant unique d’un enregistrement
Clé étrangèreChamp qui renvoie à la clé primaire d’une autre table (ex : id_auteur dans la table livres)

SQL = Structured Query Language, utilisé dans MySQL, PostgreSQL…

Les outils

  • Microsoft Access - payant, et utilisé en entreprise et dans les administrations ;
  • LibreOffice Base - gratuit & open-source. Essaie de reproduire l’outil de Microsoft ;
  • Airtable / NocoDB / Baserow - Outil en ligne permettant de créer des bases de données sans utiliser de codes ;
  • MySQL / PostgreSQL… outils pour développeurs.

Démonstration sur NocoDB

4. Et l’IA dans tout ça ?

Traitement de la donnée facilité

  • Un fichier et une consigne bien écrite (prompt) suffisent pour nettoyer, résumer ou représenter des données
  • Le mode agentique : l’IA enchaîne elle-même les étapes, du nettoyage à la visualisation
  • Intégrée aux outils du quotidien (Word, Excel, Notion, etc.)

Un risque pour les données

  • Confidentialité : ne confier à un outil grand public que ce qu’on pourrait publier
  • Hallucinations : chiffres, textes de loi ou références inventés → toujours vérifier
  • Biais : l’IA reproduit ceux de ses données d’entraînement

À retenir

  1. Chercher : opérateurs, filtre par date, lire une page de résultats ; veiller avec RSS et alertes
  2. Vérifier : qui, quand, croiser, lecture latérale, recherche inversée
  3. Gérer : formats ouverts, critères de fiabilité, base légale RGPD, sauvegarde 3-2-1, nommage ISO
  4. Traiter : tableur pour les listes, base de données pour les relations ; le bon graphique pour le bon message
  5. IA : un gain de temps, à condition de protéger les données et de tout vérifier
